# Spring Boot Student CRUD API

A beginner-friendly Spring Boot REST API that demonstrates how a backend application connects a client, server, and MySQL database to perform CRUD operations on student records.

The project follows a layered structure using **Controller → Service → Repository → Entity**, with **Spring Data JPA** handling database interaction so that common SQL queries do not need to be written manually.

## Features

* Create student records
* Read a single student by ID
* Read all students
* Update an existing student
* Hard-delete a student
* Soft-delete a student by marking it as deleted
* Connect Spring Boot with MySQL
* Automatically create/manage the student table through JPA/Hibernate configuration
* Test APIs using Postman
* Observe the SQL generated by Hibernate

## REST API

| Operation        | HTTP Method | Example Endpoint     | Body           |
| ---------------- | ----------- | -------------------- | -------------- |
| Create student   | `POST`      | `/api/students`      | Student JSON   |
| Get all students | `GET`       | `/api/students`      | None           |
| Get one student  | `GET`       | `/api/students/{id}` | None           |
| Update student   | `PUT`       | `/api/students/{id}` | Student JSON   |
| Delete student   | `DELETE`    | `/api/students/{id}` | None           |
| Soft delete      | `PATCH`     | `/api/students/...`  | As implemented |

> The transcripts demonstrate the soft-delete flow with a `PATCH` request and a dedicated soft-delete path, but do not provide a complete, unambiguous final endpoint string. Use the exact mapping present in your source code.

## Student Entity

The student record demonstrated in the project contains fields such as:

* `id`
* `name`
* `email`
* `age`
* `rollNumber`
* `subject`
* `isDeleted` for the soft-delete flow

The `id` acts as the primary key, with a `Long` type used by the repository.

## Spring Data JPA

The repository follows the pattern:

```java
public interface StudentRepository
        extends JpaRepository<Student, Long> {
}
```

Important methods discussed include:

```java
save(...)
findAll()
findById(...)
deleteById(...)
existsById(...)
```

Spring Data JPA provides the implementation of these common repository operations at runtime, eliminating the need to manually implement basic SQL operations.

## CRUD Operations

### Create

```text
POST /api/students
Content-Type: application/json
Accept: application/json
```

Example:

```json
{
  "name": "Aditya",
  "email": "aditya@gmail.com",
  "age": 28,
  "rollNumber": 1001,
  "subject": "Spring Framework"
}
```

The record is persisted using the repository's `save()` method.

### Read All

```text
GET /api/students
```

The service can use:

```java
studentRepository.findAll();
```

### Read One

```text
GET /api/students/{id}
```

Example:

```text
GET /api/students/1
```

The ID is received as a path variable and passed to:

```java
studentRepository.findById(id);
```

If the record does not exist, the controller can return `404 Not Found`.

### Update

```text
PUT /api/students/{id}
```

Example:

```json
{
  "name": "Rohit",
  "email": "rohit@gmail.com",
  "age": 28,
  "rollNumber": 105,
  "subject": "Spring Framework"
}
```

The same `save()` method can be used for both creating and updating records. JPA determines whether the operation should result in an insert or update based on the entity's identity.

### Hard Delete

```text
DELETE /api/students/{id}
```

The repository provides:

```java
studentRepository.deleteById(id);
```

A hard delete removes the record from the database.

### Soft Delete

Soft deletion does not physically remove the database row.

Instead, the record is marked as deleted using the `isDeleted` field.

```text
isDeleted = 0  → active
isDeleted = 1  → deleted
```

The record remains in the database but should be excluded from normal listings.

## Database Configuration

The project uses MySQL.

Default ports demonstrated:

```text
Spring Boot → 8080
MySQL       → 3306
```

Database configuration is placed in:

```text
src/main/resources/application.properties
```

Example:

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/student_crud_db
spring.datasource.username=<your-username>
spring.datasource.password=<your-password>

spring.jpa.hibernate.ddl-auto=<your-config>
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
```

> Replace the placeholders with your local configuration. Never commit real database credentials.

## Generated SQL

With:

```properties
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
```

Hibernate can display the SQL generated for operations such as:

```java
save()
findAll()
findById()
deleteById()
```

This helps visualize what Spring Data JPA is doing internally.

## Postman Testing

Postman is used as the client for testing the REST API.

For JSON requests:

```text
Accept: application/json
Content-Type: application/json
```

Recommended testing order:

1. Start MySQL.
2. Start the Spring Boot application.
3. Confirm the application is running on port `8080`.
4. Create a student with `POST`.
5. Verify the record in MySQL/DBeaver.
6. Retrieve the student with `GET`.
7. Retrieve all students.
8. Update a student with `PUT`.
9. Verify the update in the database.
10. Test hard deletion with `DELETE`.
11. Test soft deletion with `PATCH`.
12. Verify the soft-deleted record remains in the database but is marked deleted.

## Running the Project

### Prerequisites

* Java
* Maven
* MySQL Server
* Postman
* IntelliJ IDEA or another Java IDE

### 1. Clone the project

```bash
git clone <your-repository-url>
cd <project-directory>
```

### 2. Create the database

```sql
CREATE DATABASE student_crud_db;
```

### 3. Configure MySQL credentials

Update:

```text
src/main/resources/application.properties
```

with your local username and password.

### 4. Start the application

```bash
mvn spring-boot:run
```

Or run the main Spring Boot application class from your IDE.

### 5. Test the API

Use:

```text
http://localhost:8080
```

with the endpoints described above.
